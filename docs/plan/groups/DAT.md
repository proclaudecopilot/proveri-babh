## DAT-001 · Неизменяеми оригинали и произход

Съхранявай файлове, sheet, ред, клетка, сурова стойност и версия на parser; не режи текст до UI/SQL лимит.

- **Приоритет / етап / вълна:** P0 / R1 / 4
- **Резултат:** raw/source schema и repository
- **Зависимости:** ARC-005
- **Основание:** IM-07 · покрива: IM-07
- **Статус:** planned

**Приемане**

- 100% от приетите полета сочат към оригинал
- Дълъг състав и фирма се пазят без загуба

**Конкретна проверка:** Импортирай състав над 5000 и име на фирма над 490 символа.

## DAT-002 · Стабилна идентичност на регистрация

Използвай вътрешен ID и доказан source key; пази регистрационния номер като текст; различавай липсващ ID и конфликт.

- **Приоритет / етап / вълна:** P0 / R1 / 5
- **Резултат:** registration identity service
- **Зависимости:** DAT-001
- **Основание:** IM-06 · покрива: IM-06
- **Статус:** planned

**Приемане**

- Еднакъв номер в един scope не създава два активни записа
- Конфликтните редове не се решават с first wins

**Конкретна проверка:** Два различни реда с един номер попадат в преглед с двата оригинала.

## DAT-003 · Пълна история на полетата

Версионирай всички бизнес полета; отдели raw hash от normalized hash и derivation version; историята пази причина и източник.

- **Приоритет / етап / вълна:** P0 / R1 / 6
- **Резултат:** record_versions и field_diff service
- **Зависимости:** DAT-002
- **Основание:** IM-01, IM-10 · покрива: IM-01, IM-10
- **Статус:** planned

**Приемане**

- Промяна само в дата, фирма или бележка създава diff
- Повторен идентичен импорт не създава нова бизнес промяна

**Конкретна проверка:** Промени поотделно всяко поле и сравни точния diff.

## DAT-004 · Изолирани версии на наборите

Обработвай в staging dataset; публичният API чете само активната валидирана версия, включително фирми и индекси.

- **Приоритет / етап / вълна:** P0 / R1 / 7
- **Резултат:** dataset lifecycle и read context
- **Зависимости:** DAT-003
- **Основание:** IM-04 · покрива: IM-04
- **Статус:** planned

**Приемане**

- Няма TRUNCATE или частично обновяване на активния набор
- Свързаните заявки ползват един dataset_version

**Конкретна проверка:** Чети продукт и фирмени броячи по време на rebuild и сравни версиите.

## DAT-005 · Атомарно публикуване

Публикувай с един проверен switch след всички валидатори; DB грешка спира commit и прогреса.

- **Приоритет / етап / вълна:** P0 / R1 / 8
- **Резултат:** publisher transaction и readiness checklist
- **Зависимости:** DAT-004
- **Основание:** IM-02, IM-09 · покрива: IM-02, IM-09
- **Статус:** planned

**Приемане**

- Грешка в запис или индекс не премества active pointer
- Успех се отчита само след успешен commit

**Конкретна проверка:** Инжектирай SQL отказ непосредствено преди публикация.

## DAT-006 · Отделни оси за статус

Моделирай presence, source deletion note и quality отделно; missing се изчислява само между съпоставими пълни снимки.

- **Приоритет / етап / вълна:** P0 / R1 / 9
- **Резултат:** status policy
- **Зависимости:** DAT-005
- **Основание:** IM-03, OV-05 · покрива: OV-05, IM-03
- **Статус:** planned

**Приемане**

- Непълен пакет никога не заличава/маркира липсващи масово
- Източниковата бележка остава видима и при повторна поява

**Конкретна проверка:** Сравни непълна снимка, после пълна с една липса и последващо завръщане.

## DAT-007 · Корекции като отделен слой

Админ корекция съдържа автор, основание, доказателство и обхват; не променя оригиналния запис.

- **Приоритет / етап / вълна:** P0 / R1 / 7
- **Резултат:** correction overlays и conflict model
- **Зависимости:** DAT-003
- **Основание:** DESIGN · покрива: DESIGN
- **Статус:** planned

**Приемане**

- Видими са source value и corrected value
- Нова източникова стойност поражда проверка на конфликт

**Конкретна проверка:** Коригирай фирма, после импортирай нова различна стойност.

## DAT-008 · Rollback с проследимост

Върни активната версия чрез контролирана операция; запази истории, плащания и частни данни извън rollback на регистъра.

- **Приоритет / етап / вълна:** P0 / R1 / 9
- **Резултат:** rollback service и runbook
- **Зависимости:** DAT-005
- **Основание:** DESIGN · покрива: DESIGN
- **Статус:** planned

**Приемане**

- Rollback възстановява консистентни данни и индекси
- Не възстановява изтекъл PRO достъп и не повтаря известия

**Конкретна проверка:** Публикувай B, върни A и публикувай B отново.

## DAT-009 · Ограничения и индекси

Добави unique/check constraints според DB възможностите, индекси по scope/version/key и query plans.

- **Приоритет / етап / вълна:** P1 / R1 / 8
- **Резултат:** schema constraints и EXPLAIN evidence
- **Зависимости:** DAT-004
- **Основание:** CO-09 · покрива: CO-09
- **Статус:** planned

**Приемане**

- Дублирани активни ключове са невъзможни
- Основните заявки имат проверени индекси

**Конкретна проверка:** Изпълни конкурентен запис на един ключ и тежък company filter.

## DAT-010 · Версия в кеша и последователни четения

Ключовете включват dataset, derivation и разрешен tenant context; стар кеш не замества нов набор.

- **Приоритет / етап / вълна:** P1 / R1 / 9
- **Резултат:** cache policy и version token
- **Зависимости:** DAT-005
- **Основание:** DESIGN · покрива: DESIGN
- **Статус:** planned

**Приемане**

- Числа, списъци и CSV за един request context ползват една версия
- Частен резултат не попада в публичен кеш

**Конкретна проверка:** Публикувай нова версия между първа и втора страница.

## DAT-011 · Политика за съхранение и заличаване

Определи срокове по клас данни, legal hold и ограничения за лични данни; архивирай източници без смесване с профили.

- **Приоритет / етап / вълна:** P1 / R3 / 5
- **Резултат:** retention policy и purge jobs
- **Зависимости:** DAT-001, ARC-007
- **Основание:** DESIGN · покрива: DESIGN
- **Статус:** planned

**Приемане**

- Публичен източник и частен акаунт имат отделни правила
- Заличаване на акаунт не руши регистъра или счетоводния журнал

**Конкретна проверка:** Пробно изтриване на тестов акаунт с export, watch и billing записи.
